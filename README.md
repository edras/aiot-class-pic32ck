## About

This repository is the lab material for the **Industrial IoT** class. Students
build a connected sensor system using Microchip PIC32CK microcontrollers,
10BASE-T1S Single Pair Ethernet and the MQTT protocol.

The class focuses on two board roles:

| Board | Role |
|-------|------|
| **Smart Sensor** | Reads air-quality sensors (CO2, temperature, humidity, PM, VOC) and publishes the data over MQTT |
| **Demo** | All-in-one demo board that combines sensor, HMI and I/O functions |

Each board connects to a **10BASE-T1S** multidrop Ethernet segment using a
LAN865x MAC-PHY, runs a lightweight IP stack (lwIP) and communicates with an
MQTT broker. A **Node-RED** dashboard (included) visualises the sensor data in
real time.

## Hardware

### MCU and Board

| MCU | Board |
|-----|-------|
| PIC32CK2051SG01064 | PIC32CK SG01 Curiosity Nano (EV33V87A) |

The Curiosity Nano is mounted on a
[Curiosity Nano Base for Click boards (AC164162)](https://www.microchip.com/en-us/development-tool/AC164162).
Every networked board uses a
[Two-Wire ETH Click (MIKROE-5543)](https://www.mikroe.com/two-wire-eth-click)
for 10BASE-T1S connectivity.

### Smart Sensor Click Boards (air quality)

Sensors are detected at start-up; only the topics of detected sensors are
published.

| Module | Description |
|--------|-------------|
| [HVAC Click (MIKROE-4290)](https://www.mikroe.com/hvac-click) | Sensirion SCD41 — CO2, temperature, humidity |
| [Sensirion SEN5x (SEN55)](https://sensirion.com/products/catalog/SEK-SEN5x) | PM1/2.5/4/10, VOC, NOx, temperature, humidity |
| MIKROE-5908 (APC1) | Temperature, humidity, VOC, CO2, AQI, PM |
| MIKROE-5761 (BME280) | Temperature, humidity, pressure |
| [OLED C Click (MIKROE-1585)](https://www.mikroe.com/oled-c-click) | Status display / alarm |

### Network

A gateway device at **192.168.0.5** bridges the 10BASE-T1S segment to the
regular Ethernet network where the MQTT broker and the Node-RED dashboard run.

├── .vscode/                          # VS Code workspace

│   ├── src/                          # shared application source
│   │   ├── main.c, app.c, tasks.c, terminal.c, board_types.h
│   │   ├── hal/<board>_pic32ck/      # board-specific HAL
│   │   ├── MQTT/                     # topic abstraction layer
│   │   ├── T1S/                      # LAN865x / TC6 + lwIP glue

`cmake/`, `_build/` and `out/` are generated by the MPLAB VS Code extension —
do not edit them (except `cmake/**/user.cmake`, see the
[PIC32CK Programming Guide](docs/PIC32CK_Programming_Guide.md)).

## Getting Started

### Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Visual Studio Code | latest | |
| MPLAB Extension Pack for VS Code | latest | Build, debug, MCC |
| MPLAB XC32 | v5.00 | C compiler for PIC32CK |
| Device packs | PIC32CK-SG_DFP, CMSIS | Downloaded automatically by the extension |

On Windows, enable long paths if you hit path-length errors (see
[MPLAB_to_VSCode_Migration.md](docs/MPLAB_to_VSCode_Migration.md) if
available).

### Clone

```bash
git clone <repository-url>
cd aiot-class-pic32ck
```

### Build

1. Open the repository root folder in VS Code.
2. Build `AIoT_PIC32CK_Secure : pic32ck_secure` **once** — this produces the
   secure image that every PIC32CK board needs.
3. Open the **MPLAB** view and select the project and configuration you want
   (e.g. `AIoT_Smart_Sensor : smart_sensor_pic32ck`).
4. Build with the MPLAB build action or `Ctrl+Shift+B`.

> **Important:** PIC32CK is a TrustZone device. Always program the
> `*-unified.hex` (which merges the secure and non-secure images). Read the
> [PIC32CK Programming Guide](docs/PIC32CK_Programming_Guide.md) before
> flashing.

### Program and Debug

Use the **Run and Debug** view in VS Code. The launch configurations are:

| Configuration | Action |
|---------------|--------|
| Debug AIoT_Smart_Sensor: smart_sensor_pic32ck (unified) | Build, flash and debug the Smart Sensor |
| Run AIoT_Smart_Sensor: smart_sensor_pic32ck (unified) | Build and flash without debugger |
| Debug AIoT_Demo: demo_pic32ck (unified) | Build, flash and debug the Demo board |
| Run AIoT_Demo: demo_pic32ck (unified) | Build and flash without debugger |

Each configuration automatically builds the project before flashing.

## Network and MQTT

### IP Addresses

Addresses are derived from `BOARD_TYPE` in `firmware/src/board_types.h`:

| Board | `BOARD_TYPE` | IP Address | MQTT Node Name |
|-------|--------------|------------|----------------|
| Smart Sensor | `SMART_SENSOR_BOARD` | 192.168.0.100 | `smart_sensor` |
| Demo | `DEMO_BOARD` | 192.168.0.104 | `demo` |
| Gateway | — | 192.168.0.5 | — |

The gateway address (192.168.0.5) is also used as the MQTT broker address
(`firmware/src/MQTT/mqtt_topics.c`).

### MQTT Topics

Topics follow the pattern `<board>/<module>/<parameter>`, for example
`smart_sensor/mikroe4290/CO2`.

**All boards**

| Topic | Direction | Description |
|-------|-----------|-------------|
| `<board>/curiosity/sw0` | UP | On-board button |
| `<board>/curiosity/led0` | DOWN | On-board LED |
| `<board>/curiosity/mcu_uid` | UP | MCU unique ID |
| `<board>/curiosity/firmware` | UP | Firmware revision |

**Smart Sensor / Demo** — published only if the sensor is detected

| Module | Parameters | Direction |
|--------|------------|-----------|
| `mikroe4290` (SCD41) | `CO2`, `temperature`, `moisture` | UP |
| `sen5x` | `temperature`, `moisture`, `voc`, `nox`, `pm1`, `pm25`, `pm4`, `pm10` | UP |
| `mikroe5908` (APC1) | `temperature`, `moisture`, `voc`, `co2`, `aqi`, `pm1`, `pm25`, `pm10` | UP |
| `mikroe5761` (BME280) | `temperature`, `moisture`, `pressure` | UP |

### Testing with Mosquitto

```bash
# Subscribe to all topics
mosquitto_sub -h 192.168.0.5 -t "#" -v

# Toggle the on-board LED
mosquitto_pub -h 192.168.0.5 -t "smart_sensor/curiosity/led0" -m "true"
```

## Firmware Architecture

### TrustZone Dual-Image (PIC32CK)

PIC32CK SG01 is a TrustZone-M device. The firmware is split into:

| Image | Project | Output |
|-------|---------|--------|
| Secure | `AIoT_PIC32CK_Secure : pic32ck_secure` | `out/AIoT_PIC32CK_Secure/pic32ck_secure.elf` |
| Non-secure (Smart Sensor) | `AIoT_Smart_Sensor : smart_sensor_pic32ck` | `out/AIoT_Smart_Sensor/smart_sensor_pic32ck.elf` |
| Non-secure (Demo) | `AIoT_Demo : demo_pic32ck` | `out/AIoT_Demo/demo_pic32ck.elf` |
| **Unified (what you flash)** | built by non-secure project | `out/AIoT_Smart_Sensor/smart_sensor_pic32ck-unified.hex` |

### Shared Harmony Project

The `harmony/AIoT_PIC32CK/` folder contains the Harmony / MCC project shared
by all PIC32CK board configurations. A change there affects every board.

### Portable Hardware Layer

All boards share one common application and driver code base in `firmware/src/`.
Board-specific code lives in HAL files under `firmware/src/hal/<board>_pic32ck/`.
Module drivers never call Harmony directly — they go through their HAL file,
which makes the software portable across boards and MCU architectures.

| Layer | Location |
|-------|----------|
| Application and module drivers | `firmware/src/`, `firmware/src/<MODULE>/` |
| Board-specific HAL | `firmware/src/hal/<board>_pic32ck/` |
| Harmony peripheral libraries | `harmony/AIoT_PIC32CK/` |

## Serial Terminal

Connect to the Curiosity Nano virtual COM port at **115200 8N1** before
resetting the board.

| Key | Function |
|-----|----------|
| `w` | Print sensor readings |
| `v` | Toggle CSV output of published values |
| `c` | Redraw header |
| `d` | Debug mode |
| `b` | Bridge mode to the COMM module |
